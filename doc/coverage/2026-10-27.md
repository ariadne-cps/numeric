## Final exponent-type audit

The first number.cpp simplification incorrectly equated the checked `long`
returned by get_si() with the actual exponent type, `Int=int`. On LP64
platforms those ranges differ. The final code obtains `z.get<Int>()`
directly, checking the correct destination before invoking either power
backend. Reuse all 27 independently generated conversion boundary inputs:
both wrappers reject every out-of-range exponent, binary64 additionally
checks every valid boundary with base one, including INT_MIN. FloatMP's
valid power checks stay small because its exact intermediate significand
can be huge even for a final value of one. Integer conversion itself checks
all valid int boundaries against the frozen 32-bit expectations.

These tests also expose signed negation of INT_MIN in double pow_rnd.
Form its unsigned magnitude as `Nat(-(n+1))+Nat(1)`, preserving the valid
power operation without signed overflow. Existing positive and negative
power behavior remains covered.
